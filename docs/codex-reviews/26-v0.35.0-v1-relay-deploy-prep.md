## Scope

PKG-A-4 adds an OpenAI-compatible `/v1/*` reverse-proxy handler to the coai backend so that aidesk (and any OpenAI-SDK client) can use greentokey as an LLM relay:

```
aidesk  →  POST https://www.greentokey.com/v1/chat/completions
           Authorization: Bearer sk-<greentokey user key>
              ↓  coai backend relay handler
           NewAPI :3000/v1/chat/completions
           Authorization: Bearer sk-<relay_token>  (internal, never public)
```

**Three-layer isolation preserved**: NewAPI `:3000` has no Caddy public route. The relay handler is the only internal bridge.

## Auth Flow (handler)

1. `AuthMiddleware` already ran; sets `"auth"=true` + `"user"=<username>` in gin context when `Bearer sk-xxx` is valid.
2. Handler reads `auth` from context — if false → `401 invalid_api_key`.
3. Resolves `coai_user_id` via `SELECT id FROM auth WHERE username=?`.
4. Calls `newapi.LoadBinding(db, coaiUserID)` → `gtk_newapi_binding` row.
   - `sql.ErrNoRows` → `401 no_upstream_binding` ("purchase a token plan first").
5. Builds upstream URL: `newapi.base_url + /v1 + <path>` (query string preserved).
6. Copies all non-hop-by-hop request headers; **rewrites** `Authorization: Bearer <relay_token>`.
7. Streams response back verbatim (4KB chunks with `http.Flusher` flush for SSE).

## Production Config Change Required

On the VPS, before deploying v0.35.0:

```bash
# /opt/greentokey/config.yaml  (or .env equivalent)
newapi:
  relay_token: "sk-EZKyGzC1r2Dxves1Q0wlpSNAjFiyZg79jCHYl4oYuibhJof9"
```

This is NewAPI token **id=6**, owned by admin user id=2, with unlimited quota. It is the sk-xxx used for ALL relay traffic (user identity is coai-side, NewAPI just sees one token).

Without this config, the handler falls back to `admin_access_token` with a WARN log — NewAPI `/v1` endpoints require `sk-xxx` format (`Bearer` prefix), not the bare admin token, so relay calls will likely get `401` from NewAPI until `relay_token` is set.

## Deploy Steps

```bash
# 1. Merge branch
git checkout feat/v0.22-token-launch
git merge --no-ff feat/v0.35-v1-relay-proxy

# 2. Set relay_token in production config (see above)

# 3. Build + deploy (same Dockerfile.split pattern as v0.34.0)
cd app && npm run build          # frontend (unchanged)
rsync -az dist/ vps:/opt/greentokey/coai/app/dist/
docker build -f Dockerfile.split -t greentokey-coai:v0.35.0-v1-relay .
# Update docker-compose.yml image tag → v0.35.0-v1-relay
docker compose up -d coai
```
