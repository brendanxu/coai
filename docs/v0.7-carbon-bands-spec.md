# v0.7 — Carbon precision: bands + confidence + real-time grid

> Drafted: 2026-04-28
> Triggered by: /codex review of v0.6 Window B (8 BLOCKERS, 4 IMPORTANT findings on
> point-estimate-plus-tight-margin defensibility)
> Ship narrative: **"greentokey carbon, now with real-time precision."**
> Status: spec only — no code. Lands after v0.6 north-star (2026-06-06) checkpoint.

## Why

v0.6 ships with single-value coefficient midpoints + ±100% declared margin + an
Acknowledged Limitations section. That's defensible v1 — honest about the gap
between displayed precision and real-world variance. But it's not the moat.

The moat is **showing actual bands and confidence**, sourced from **real-time
data**, **per-region**. That's what greentokey can ship in v0.7 that no other
indie carbon tracker is doing today (Cal.com / Plausible / Patagonia digital are
good references for transparency tone, but none of them ship live carbon for
LLMs).

If we hit the v0.6 north-star (5 paying customers ≥$15/mo by 2026-06-06), v0.7
becomes the second-act story for the next ICP wave: "they were transparent in v1,
now they're precise."

## Scope (locked targets)

### F1. Coefficient bands instead of midpoints

`carbon_factors.json` schema gains `band_low_g` and `band_high_g` per entry, plus
a `confidence` enum:

```json
{
  "model": "gpt-4",
  "region": "us-east",
  "band_low_g": 1.2,
  "band_mid_g": 1.4,
  "band_high_g": 1.6,
  "confidence": "low",   // low | medium | high
  "sources": ["jegham-2025"],
  "valid_from": "2026-07-01",
  "version": "2026-07"
}
```

The CarbonBadge tooltip surfaces the band: "0.7g–1.6g · likely ~1.4g". The
dashboard hero shows the midpoint with a small band indicator next to it
("12.3g · 9–15g range"). Methodology page coefficient table gains 2 columns.

**Confidence ranking**:
- `high` (≥3 independent inference studies converge within ±20%): currently nothing qualifies
- `medium` (vendor disclosure + 1 independent study): ~0 models today
- `low` (model-class extrapolation from a band of similar models): everything in v0.6

### F2. Real-time ML-CO2 API integration

Replace static `data/carbon_factors.json` with a live fetch from
[mlco2.github.io/impact](https://mlco2.github.io/impact/) — they expose a
calculation API + maintain quarterly-updated coefficients. Cache for 24h
locally; fall back to embedded snapshot on outage.

**Architecture**:
- Backend: new `carbon/factors_live.go` periodic refresh goroutine, 24h cycle.
  Persists last-good response to `~/state/carbon-factors.json`. On startup,
  prefer disk snapshot, then network refresh.
- Frontend: `getCarbonFactors()` hits `/api/carbon/factors` which returns the
  cached live response. Methodology page gains a "Last refreshed: <date>"
  footer line.

**Fallback chain**:
1. Live ML-CO2 API (24h cache)
2. Disk snapshot from previous successful refresh
3. Embedded JSON shipped in binary (current v0.6 fallback)

If all 3 fail, badge shows `~?g · v?` and methodology page shows a banner.

### F3. Per-region grid factors

Coefficient table gains a region column populated for: `us-east`, `us-west`,
`eu-west`, `eu-north`, `ap-southeast`, `ap-northeast`, `default`. Routes to
each provider's actual datacenter when the upstream API exposes location
(currently only Azure OpenAI deployments — extend as more providers add the
header).

Frontend: badge tooltip says "Region: us-east-1 (~310 gCO2e/kWh)" instead of
the global default. Dashboard adds a "Region mix" section.

**Source for grid factors**: IEA quarterly grid model + ElectricityMaps API
(real-time when budget allows; static snapshot otherwise).

### F4. Surface bands on the badge

Today the badge shows "0.42g · GPT-4o". v0.7: "0.3–0.6g · GPT-4o · low confidence".
Tier color logic adapts: tier becomes "high" when the BAND HIGH is in tier-high
range, regardless of midpoint. Conservative — surfaces uncertainty correctly.

## Risks

| # | Risk | Mitigation |
|---|---|---|
| R1 | ML-CO2 API goes down or changes shape | 3-tier fallback chain (live → disk → embedded) |
| R2 | Bands feel less actionable to users than single numbers | Show midpoint prominently, band as secondary visual |
| R3 | "Confidence: low" everywhere makes us look uncertain | Reframe in copy: "Honest uncertainty is the moat" |
| R4 | Per-region routing only covers ~10% of upstream APIs | Document clearly; show "global default" badge tag for unknown regions |
| R5 | /codex re-review on v0.7 still finds BLOCKERs | Better tooling won't fix the underlying inference uncertainty problem; we just have to be more honest about it. v0.8 might need actual partnership with provider for telemetry. |
