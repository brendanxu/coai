## What ships

User-visible:
1. **CarbonBadge** under every completed AI message — tier-colored (fern/sage/sun, never red), Radix tooltip with coefficient + ±20% disclaimer.
2. **MonthlyWidget** at the top of the chat sidebar — month total + delta vs last month, click → `/dashboard`.
3. **`/dashboard`** — single-column editorial layout (Stripe Climate / Patagonia / Cal.com reference): hero number, by-model bars (plain DOM, no chart lib), equivalent narrative ("≈ 1.2 km of city driving"), share-card PNG button, methodology link.
4. **`/methodology`** — long-form transparency essay, founder-signed, with "what we don't measure" honesty section that anchors the anti-greenwashing claim.
5. **EcoModeToggle** — leaf-icon button left of send. Click → toggle persistent eco_mode. Long-press → "off this turn" 60s override (sets `X-Eco-Override: off` header).

Backend:
- `usage_carbon` and `user_carbon_prefs` tables (idempotent CREATE TABLE IF NOT EXISTS, registered in `connection/db_migration.go` for both MySQL and SQLite).
- New isolated package `chat/carbon` with: factor cache (embedded JSON), Eco router, fire-and-forget usage logger, REST API handlers.
- Surgical hooks in `manager/chat_completions.go`: 1 import + 1 helper + 5 call sites; eco-route runs **before** quota check so user is billed cheaper too.
- New Go endpoints (auth required): `/api/carbon/summary`, `/api/carbon/by-model`, `/api/carbon/factors`, `/api/user/eco-mode` (GET/PUT), `/api/user/eco-mode/feedback-seen` (POST).

## Deploy notes (for the joint VPS deploy)

Both Window A and Window B branches must be merged into `greentokey-main` before deploy. Suggested sequence:

1. Merge Window A's PR first (Window A is ready and waiting, per founder).
2. Rebase `feat/v0.6-window-b` onto updated `greentokey-main`. Resolve:
   - `main.go` — both sets of changes coexist (different lines).
   - `connection/db_migration.go` — both append SQL blocks; preserve both.
   - `app/store/index.ts` — both add reducer entries; preserve both.
   - `app/router.tsx` — both add routes; preserve both.
   - `app/pnpm-lock.yaml` — discard, run `pnpm install` to regenerate.
3. Merge Window B's PR.
4. Deploy via `Dockerfile.split` flow:
   ```bash
   # Mac
   cd coai/app && pnpm install && pnpm run build
   rsync -avz --delete --exclude='.git' --exclude='node_modules' \
     coai/ vps:/opt/greentokey/coai-source/

   # VPS
   cd /opt/greentokey/coai-source && \
     docker build -f Dockerfile.split -t greentokey-coai:v0.6 . && \
     docker compose up -d coai
   ```
5. Verify migrations applied:
   ```bash
   docker exec greentokey-mysql mysql -uroot -p${MYSQL_PASS} chatnio \
     -e "SHOW TABLES LIKE 'usage_%'; SHOW TABLES LIKE 'user_carbon_%';"
   ```
   Expect: `usage_carbon`, `user_carbon_prefs` (mine) + Window A's tables.
6. Smoke tests:
   ```bash
   curl -s -H "Cookie: session=..." https://api.greentokey.com/api/carbon/summary | jq
   # Expect total_g=0 (no chats yet), first_month=true
   ```
7. Eco Mode E2E verification (acceptance criterion):
   ```bash
   # Toggle eco on via UI, then:
   curl -X POST 'https://api.greentokey.com/v1/chat/completions' \
     -H 'Authorization: Bearer YOUR_KEY' \
     -d '{"model":"gpt-4","messages":[{"role":"user","content":"hi"}]}'

   docker exec greentokey-newapi tail -50 /var/log/newapi/access.log | grep model=

   ```
